  • 13.56 MHz RFID (MIFARE cards and key tags) read over SPI at 1 MHz
  • MicroPython firmware checks the RC522 firmware version at boot and retries until the wiring is good
  • Debounce: holding a card on the reader counts as one tap, not ten (1.5 s window)
  • Feedback: on-board LED flashes on every accepted tap
  • Powered at 3.3 V because 5 V can damage the RC522
  • Sends UID:XX XX XX XX to the payment server over USB serial

How it runs

From card tap to M-Pesa receipt

READERESP32 + RC522 reads the card UID and sends it to the Hydra Pay server.
PAYMENTSPython server looks up the card owner and price, then sends an M-Pesa STK push through Safaricom's Daraja API.
VERIFICATIONSafaricom's callback marks the payment PAID with its M-Pesa code. If the callback is late, the server polls Daraja for up to 3 minutes.
RECORDSEvery tap and payment is saved in a SQLite database: card, amount, phone, status, M-Pesa code and time.
DASHBOARDLive web dashboard to register cards, set prices, watch payments and export records. Admin actions need a PIN.
CUSTOMERSWhatsApp receipts and a menu (my card, my payments), plus USSD for phones without internet.
Hydra Pay · Architecture
Engineering for trust

Built so a payment is never marked wrong

Verified, not claimed

Only Safaricom's result can set a payment to PAID. Cancelled or unanswered prompts are recorded as NOT PAID with the reason.

Two paths to the answer

Callback first, polling as backup. "Still processing" is treated as pending, not as failed.

Recorded exactly once

A lock ensures each payment is finalised once, even when the callback and polling answer together.

No double charging

A card can't get a second prompt while one is still waiting on the owner's phone.
